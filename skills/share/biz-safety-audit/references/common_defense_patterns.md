# 通用防御模式参考

供 `content` / `interaction` / `sms` 三个路由按需引用，提供限流算法、熔断、黑白名单等通用模式的选型指引。

---

## 1. 限流算法

### 1.1 固定窗口（Fixed Window）

- **原理**：将时间划分为固定大小的窗口（如 1 分钟），窗口内计数，超限拒绝
- **优点**：实现简单，内存开销小
- **缺点**：窗口边界处存在突刺（两个窗口交界处瞬间可承受 2 倍流量）
- **适用**：低精度场景、辅助限流

### 1.2 滑动窗口（Sliding Window）

- **原理**：基于当前时间点向前看一个窗口周期，统计请求数
- **优点**：无窗口突刺，限流更平滑
- **缺点**：实现略复杂（需记录每个请求的时间戳或用分桶近似）
- **适用**：接口限流、验证码发送频率、评论频率

### 1.3 令牌桶（Token Bucket）

- **原理**：以固定速率向桶中添加令牌，请求消耗令牌，桶空则拒绝
- **优点**：允许一定的突发流量（桶中有积累的令牌）
- **缺点**：需要定时填充机制
- **适用**：API 网关、允许短暂突发但控制平均速率的场景

### 1.4 漏桶（Leaky Bucket）

- **原理**：请求进入桶中排队，以固定速率流出处理
- **优点**：输出速率严格恒定
- **缺点**：突发流量会被排队延迟，用户体验差
- **适用**：消息队列消费、严格控制下游压力的场景

### 选型建议

| 场景 | 推荐算法 |
|------|----------|
| 短信验证码频率 | 滑动窗口 |
| API 接口限流 | 令牌桶 / 滑动窗口 |
| 评论/发布频率 | 滑动窗口 |
| 消息推送速率 | 漏桶 |
| 简单计数（辅助） | 固定窗口 |

## 2. 熔断与降级

### 2.1 熔断器模式（Circuit Breaker）

- **三态**：关闭（正常）→ 打开（拒绝请求）→ 半开（试探恢复）
- **触发条件**：连续失败率超阈值 / 响应时间超阈值
- **适用场景**：第三方审核服务调用、短信通道调用、AI 内容审核

### 2.2 降级策略

| 场景 | 降级方案 |
|------|----------|
| 敏感词服务不可用 | 进入人工审核队列 / 限制发布 |
| 短信通道不可用 | 切备用通道 / 降级为邮件验证 |
| 验证码服务不可用 | 临时提高发布门槛 / 人工处理 |
| 内容审核积压 | 先发后审但标记"待审核" |

## 3. 黑白名单

### 3.1 层级

| 层级 | 维度 | 示例 |
|------|------|------|
| IP 层 | IP / IP 段 | 爬虫 IP、代理池 IP |
| 设备层 | 设备指纹 / 设备 ID | 模拟器、已知刷量设备 |
| 账号层 | 用户 ID | 被封禁用户、高风险账号 |
| 内容层 | 关键词 / 正则 | 敏感词、广告特征 |
| 号码层 | 手机号 / 邮箱 | 被轰炸号码、虚拟号段 |

### 3.2 管理要求

- 黑白名单**可动态更新**（API / 管理后台），不需重启
- 有**过期机制**（临时封禁 vs 永久封禁）
- 变更有**审计日志**
- 白名单用于测试账号 / VIP 用户跳过部分限制，范围从严

## 4. 风险评分

对于复杂场景（如注册、下单），可引入风险评分模型：

- **输入因子**：IP 风险、设备风险、行为特征、账号年龄、历史违规
- **输出**：风险分值（0~100）
- **决策**：低风险通过 → 中风险加验证码 → 高风险拦截 + 人工审核
- **适用**：注册防刷、支付风控、内容发布风控

## 5. 分布式实现要点

- 限流计数器使用 **Redis** 等集中存储（不用本地内存，多实例会漂移）
- 分布式锁选型：Redis（Redisson）/ ZooKeeper / 数据库行锁，按场景选
- 计数器 key 设计包含：`业务类型:维度值:时间窗口`
- 所有限制配置通过**配置中心**管理，支持热更新
- 限流/熔断的触发和恢复都要有**监控指标**和**告警**
