# 交互安全审计 Checklist

## 适用场景

接口对外暴露、涉及用户交互操作（登录、注册、搜索、点赞、关注、支付、抽奖等）、可被脚本/爬虫批量调用的功能。

---

## 1. 频率限制（Rate Limiting）

### 1.1 接口级限流

- [ ] 关键接口配置了**后端限流**（不只靠前端按钮禁用）
- [ ] 限流维度合理：按 IP / 按用户 / 按设备 / 按接口组合
- [ ] 限流算法选型明确（滑动窗口 / 令牌桶 / 漏桶），见 `common_defense_patterns.md`
- [ ] 触发限流时返回明确的错误码和提示（如 `429 Too Many Requests`）
- [ ] 限流阈值可配置（不硬编码），支持按接口/场景独立调整

### 1.2 业务级频率控制

- [ ] 登录尝试限制（连续失败 N 次后锁定 / 要求验证码）
- [ ] 注册限制（同 IP / 同设备 N 分钟内限注册 M 次）
- [ ] 搜索请求限制（防止遍历式爬取）
- [ ] 点赞/关注/收藏等社交操作有频率上限
- [ ] 评论/私信发送有频率上限
- [ ] 支付/下单有频率上限（防止重复提交）

## 2. 验证码策略（CAPTCHA）

- [ ] 明确哪些场景需要验证码（注册 / 登录失败后 / 敏感操作）
- [ ] 验证码类型选型合理（滑块 / 图形 / 短信 / 行为验证）
- [ ] 验证码在**后端校验**，不在前端校验
- [ ] 验证码有过期时间（一次性使用）
- [ ] 验证码不可被暴力枚举（错误次数限制 + 过期刷新）
- [ ] 验证码服务不可用时有降级策略

## 3. 防重放与幂等

- [ ] 关键写操作（下单/支付/提交）有**幂等设计**
- [ ] 请求携带唯一标识（nonce / requestId），后端去重
- [ ] Token / 签名有时效性，过期请求拒绝
- [ ] 前端按钮提交后禁用，防止用户双击（体验层，非安全层）

## 4. 防爬与反自动化

### 4.1 爬虫检测

- [ ] 列表 / 搜索 / 详情等数据接口有**访问频率检测**
- [ ] 异常 User-Agent / 无 Referer / 无 Cookie 的请求标记为可疑
- [ ] 短时间大量请求同一资源的 IP 自动加入灰名单
- [ ] 关键数据接口不暴露完整分页参数（防止遍历全库）

### 4.2 数据保护

- [ ] 列表接口有**最大分页限制**（`pageSize` 上限）
- [ ] 搜索结果有深度限制（不允许翻到第 1000 页）
- [ ] 敏感数据（手机号/邮箱）在列表中脱敏展示
- [ ] 导出接口有权限 + 频率限制

## 5. 并发与竞态

- [ ] 库存 / 余额 / 积分等共享资源有**并发控制**（乐观锁 / 分布式锁）
- [ ] 秒杀/抽奖场景有预扣 + 确认机制，防止超卖
- [ ] 同一用户不可同时发起多笔相同操作（分布式去重）
- [ ] 定时任务有防重入机制

## 6. 会话与设备

- [ ] 异地登录 / 新设备登录有**安全通知**（可选二次验证）
- [ ] 同时在线设备数有上限
- [ ] 长时间未操作的会话自动过期
- [ ] 敏感操作（修改密码/绑定手机/提现）要求二次认证

## 7. 防刷场景专项

### 7.1 营销活动防刷

- [ ] 优惠券 / 红包 / 积分发放有**总量 + 人均上限**
- [ ] 领取操作做**用户 + 设备 + IP 多维度去重**
- [ ] 活动接口有独立的高频限流配置
- [ ] 活动结束后接口及时关闭或降级
- [ ] 异常领取行为有报警（短时间大量不同账号从同一 IP 领取）

### 7.2 投票/排行防刷

- [ ] 投票有身份校验 + 频率限制
- [ ] 排行榜数据来源可审计，防止注入虚假数据
- [ ] 刷票检测（短时间集中投票、账号行为异常）

## 审计结论分级

| 级别 | 定义 | 示例 |
|------|------|------|
| **P0 阻断** | 缺失将直接导致被刷/被攻击 | 关键接口无限流、支付无幂等、库存无并发控制 |
| **P1 建议** | 缺失显著增加被滥用风险 | 登录无失败限制、搜索无频率限制、无验证码策略 |
| **P2 可选** | 提升防御深度 | 设备指纹、异地登录通知、刷票检测 |
