# 短信与通知安全审计 Checklist

## 适用场景

涉及短信验证码、营销短信、站内通知、Push 推送、邮件发送等消息下发功能。

---

## 1. 短信验证码安全

### 1.1 发送频率限制

- [ ] 同一手机号 **N 秒内**不可重复发送（通常 60s）
- [ ] 同一手机号 **每小时** 发送上限（通常 5~10 条）
- [ ] 同一手机号 **每天** 发送上限（通常 10~20 条）
- [ ] 同一 IP **每小时** 发送上限（防止换号轰炸）
- [ ] 同一设备 **每天** 发送上限
- [ ] 频率限制在**后端执行**，前端倒计时仅为体验
- [ ] 超限时返回友好提示，不暴露具体限制规则细节

### 1.2 验证码安全

- [ ] 验证码长度 ≥ 6 位（纯数字场景）
- [ ] 验证码有效期合理（通常 5~10 分钟）
- [ ] 验证码**一次验证即失效**（用后即废）
- [ ] 验证码验证有**错误次数限制**（连续错误 N 次后失效，需重新获取）
- [ ] 验证码不在接口响应中返回（禁止前端回显）
- [ ] 验证码不在日志中明文记录

### 1.3 防轰炸

- [ ] 发送验证码前要求**图形验证码 / 滑块验证**
- [ ] 对高频发送的手机号自动加入**冷却名单**
- [ ] 黑名单机制：被标记的号码暂停发送
- [ ] 异常发送量有**实时报警**（如每分钟全站发送量突增）

## 2. 营销短信 / 通知短信

### 2.1 合规要求

- [ ] 营销短信获得用户**明确授权/订阅**（opt-in）
- [ ] 提供退订入口（短信回复 TD / 系统设置关闭）
- [ ] 短信内容使用已备案的**模板**，不允许拼接任意文本
- [ ] 发送时段限制（通常禁止 21:00~8:00 发送营销类）
- [ ] 退订用户不再收到同类消息（退订生效有时效要求）

### 2.2 频率与成本管控

- [ ] 单用户每天/每周接收营销短信有上限
- [ ] 批量发送有**审批流程**或负责人确认
- [ ] 短信通道有**费用预警**（日/月消耗达阈值告警）
- [ ] 测试环境与生产环境短信通道**严格隔离**
- [ ] 有渠道优先级（站内信 > Push > 短信 > 邮件），能用低成本渠道不用高成本

## 3. 站内通知 / Push 推送

### 3.1 频率控制

- [ ] 同类通知有**合并策略**（如 "张三等 5 人点赞了你的内容"）
- [ ] 单用户每天 Push 推送有上限
- [ ] 用户可按类型关闭通知（系统通知 / 互动通知 / 营销通知分开）
- [ ] 夜间免打扰模式（或至少不发 Push）

### 3.2 内容安全

- [ ] 通知内容不泄露敏感信息（锁屏预览不显示验证码全文）
- [ ] 通知中的用户昵称/内容做**敏感词过滤**
- [ ] 通知中的链接做**域名白名单**校验

## 4. 邮件发送

- [ ] 邮件发送频率限制（同一邮箱 N 分钟内不重复发送）
- [ ] 邮件内容使用模板，不允许注入任意 HTML
- [ ] 退订链接有效且一键退订（CAN-SPAM / GDPR 合规）
- [ ] 发件域名配置 SPF / DKIM / DMARC（防止被当垃圾邮件）
- [ ] 邮件发送失败有重试策略和上限

## 5. 通用安全

- [ ] 所有消息发送都有**审计日志**（发送时间、接收人、内容摘要、状态）
- [ ] 消息通道（短信/邮件服务商）的 API Key 不硬编码在代码中
- [ ] 消息通道切换/降级策略明确（主通道挂了用备用通道）
- [ ] 敏感操作（批量发送、修改模板、修改频率限制）有权限控制

## 审计结论分级

| 级别 | 定义 | 示例 |
|------|------|------|
| **P0 阻断** | 缺失将导致被轰炸或合规风险 | 无发送频率限制、验证码明文返回、营销短信无退订 |
| **P1 建议** | 缺失显著增加滥用风险 | 无图形验证码前置、无费用预警、无夜间免打扰 |
| **P2 可选** | 提升安全成熟度 | 通知合并策略、渠道优先级、DMARC 配置 |
