# 多领域提炼示例

目标：说明本技能不绑定 RAG。Agent、BI、性能优化、skill 优化、架构治理、工程平台化等都可以提炼。

通用表达必须遵守：

```text
原系统问题 -> 解决方案 -> 带来的效果 -> 体现的能力
```

内部编号、文件名、类名、GAP 编号只放证据附录。

## Agent 示例

- 原系统问题：Agent 只能完成单步工具调用，复杂任务依赖模型临场规划，容易漏步骤、重复查找或错误调用工具。
- 解决方案：引入任务分解、工具选择约束、执行状态记录和失败重试策略，让 Agent 从"能调用工具"升级为"能稳定执行多步任务"。
- 带来的效果：复杂任务执行更可控，失败点可定位，重复调用和漏执行减少。
- 体现的能力：Agent 编排能力、工具治理能力、复杂任务执行框架设计能力。
- 证据附录：相关设计文档章节、工具注册代码、执行日志或评测结果。

## BI 示例

- 原系统问题：报表组件配置和运行态实例耦合，复制页面时容易丢配置，权限和数据口径难以统一治理。
- 解决方案：拆出 component instance 配置模型，统一后端四层接口和前端配置契约，把报表配置、实例运行和权限控制解耦。
- 带来的效果：BI 页面复刻更稳定，组件配置可复用，数据权限和展示口径更容易统一验收。
- 体现的能力：低代码/BI 平台抽象能力、前后端契约设计能力、数据权限治理能力。
- 证据附录：schema 设计、接口契约、前端配置页、权限校验点。

## RAG 示例

- 原系统问题：用户只能看到最终回答，无法判断召回效果好坏；回答不准时也不知道是检索、重排、文档状态还是引用链路出问题。
- 解决方案：建立评测入口、分项分数、链路追踪、可信引用和健康面板，把 RAG 效果问题显性化。
- 带来的效果：RAG 从黑盒问答变成可度量、可诊断、可运营的系统。
- 体现的能力：AI 系统工程能力、可观测性体系设计能力、RAG 质量治理能力。
- 证据附录：评测接口、trace、分项分数、citation、健康 dashboard。

## Skill 优化示例

- 原系统问题：AI 经常违反用户既有工作流，把规则、脚本、备份、提炼边界当成临场判断，导致重复返工。
- 解决方案：把高频失败模式沉淀为 skill 的硬门禁、标准脚本入口、坏味道库和可验证示例。
- 带来的效果：AI 协作从"靠提醒"变成"靠规则和脚本约束"，后续任务更稳定。
- 体现的能力：AI 协作治理能力、知识工程能力、可复用 workflow 设计能力。
- 证据附录：SKILL.md、references、bad_smell_registry、脚本入口、验证记录。

## 性能优化示例

- 原系统问题：接口慢但缺少分段耗时，无法判断瓶颈在数据库、缓存、远程调用还是序列化。
- 解决方案：补齐链路耗时埋点、慢 SQL 识别、缓存命中率统计和压测对照。
- 带来的效果：性能问题从"感觉慢"变成可定位、可回归验证的问题。
- 体现的能力：性能诊断能力、可观测性建设能力、容量治理能力。
- 证据附录：压测报告、trace、慢 SQL、指标面板。
