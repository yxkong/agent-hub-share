# 会话历史来源

目标：用户不需要预先指定具体片段时，技能可从可访问的 Cursor / Claude / Codex 会话历史中发现候选，再提炼高价值资产。

会话历史只是源锚点之一。设计文档、指定代码、diff、日志等见 `source_anchors.md`。

## 默认原则

- 用户给了具体片段：只处理该片段。
- 用户说"从历史会话提炼"但未指定内容：先发现可访问的会话记录，再按时间、项目、关键词做候选扫描。
- 不能访问某工具历史时，说明缺口并请求用户提供导出文件或路径。

## 来源类型

| 工具 | 常见材料 | 处理方式 |
|---|---|---|
| Cursor | agent transcript `.jsonl`、聊天导出、项目会话目录 | 读取消息、工具结果、用户纠正和验收结论 |
| Claude | conversation export、project chat、markdown/html/json 导出 | 先转成按轮次的文本，再扫描 |
| Codex | 当前线程、rollout/session jsonl、终端和工具调用记录 | 读取用户请求、assistant 行动、工具输出和最终交付 |

## 候选发现

不从第一行开始总结。先用高价值信号定位候选：

- 交付清单、阶段总结、GAP 清单
- 设计取舍、架构收敛、能力边界
- 评测、可观测性、质量门控、自动化验证
- 用户明确纠偏后形成的新方法
- 有验证结果的性能、准确率、稳定性、成本变化

低价值信号默认跳过：

- AI 没按规则执行后的修复
- 编码规范、命名约定、字段补齐
- 普通 bug 修复
- 执行流水账、agent 分工、命令拼装过程

## 输出前检查

每个候选必须带来源锚点：

- 来源工具：Cursor / Claude / Codex / pasted
- 来源范围：当前会话 / 历史 transcript / 导出文件
- 证据片段：能证明交付、决策或验证的摘要

没有来源锚点的内容只能作为 `assumption`，不能进入简历 bullet。
