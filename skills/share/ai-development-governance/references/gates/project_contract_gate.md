# Project Contract Gate

> 解决跨项目/跨技术栈任务中“各写各的、契约漂移、验证口径不一致”的返工源。它不是新流程，而是 G3 Task Contract 的跨项目补丁。

## 触发条件

- Java / Python / 前端 / SQL 任意两端以上需要同步。
- 共享 MySQL 表、DTO、API、菜单权限、状态枚举、配置 key 有变化。
- 项目技能之间出现冲突口径，例如 Java DDL 与 Python ORM、后端 DTO 与前端字段、设计文档与当前代码不一致。
- 用户要求“跨项目空间验证”“把其他工作区结论用于本项目”。

## 必填项

| 项 | 要求 |
|---|---|
| 真源 | 写明当前以代码、DDL final、设计文档、线上配置、还是用户给定材料为准 |
| 参与项目 | 列出项目/模块/技能名，不用泛称“后端/前端” |
| 契约面 | API、DTO、DB、权限、状态、配置、UI 回显、CLI 输出等命中项 |
| 允许改 | 文件/目录白名单，越小越好 |
| 禁止改 | 明确不碰的项目、目录、online SQL、公共基类、兼容别名等 |
| 验证证据 | 按 `delivery-workflow/references/gates/mainline_evidence_matrix.md` 填证据等级 |
| 不一致处理 | 发现漂移时先登记差异与真源裁决，不用兼容层掩盖 |

## 阻断项

- 共享 DB 表未确认真源，却同时改 Java DDL 与 Python ORM。
- 后端字段、前端回显、数据库列三者只改一端。
- 为了通过当前任务修改公共基类、全局序列化、全局路由、online SQL，且没有 ADR/人工确认。
- 只给静态证据，却把跨项目能力表述为“已闭环”。
