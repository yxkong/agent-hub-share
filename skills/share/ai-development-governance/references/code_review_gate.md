# Code Review Gate（G5 补充）

> G5 Quality Gate 验证"功能是否正确"（测试通过）；本文件验证"代码是否合格"（可维护、可扩展、符合项目架构）。两者互补，共同构成 G5 的完整门禁。

## 触发条件

满足**任一**条件必须执行：

- 新增或修改了 ≥1 个业务逻辑文件
- AI 生成的代码准备合并
- 涉及接口签名、数据模型、状态机变化
- 重构或迁移改动
- Full Path 交付前

## 检查项

### 命名与可读性

- [ ] 类名、方法名、变量名语义清晰，符合项目命名约定
- [ ] 方法职责单一，不超过合理长度（建议 ≤50 行逻辑）
- [ ] 无魔法数字 / 魔法字符串（应为常量或枚举）
- [ ] 注释只解释 why / 约束 / 非显而易见的决策，不复述代码

### 架构符合度

- [ ] 代码放在项目约定的分层目录（controller / service / repository / domain）
- [ ] 依赖方向正确（上层→下层，不反向引用）
- [ ] 不引入未对齐的新模式（如项目用 Repository 但新代码用 Mapper 直调）
- [ ] 跨模块调用走约定的接口/Facade，不直接引用内部实现

### 错误处理

- [ ] 异常不被吞掉（catch 后有处理：日志 / 转义 / 重抛）
- [ ] 业务异常和系统异常分离（业务错误不用 RuntimeException 笼统抛）
- [ ] 外部调用（HTTP / MQ / DB）有超时和失败处理
- [ ] 资源（连接 / 流 / 锁）在 finally / try-with-resources 中释放

### 数据与 SQL

- [ ] 新表 / 新字段有注释、类型合理、索引合理
- [ ] 查询避免全表扫描（WHERE 条件命中索引）
- [ ] 批量操作有分批处理（不一次 INSERT 10 万行）
- [ ] N+1 查询已优化为批量查询

### 重复与复用

- [ ] 不存在与项目已有代码功能重复的新实现
- [ ] 工具方法复用项目已有的 utils / common，不另起炉灶
- [ ] 配置项走配置中心 / properties，不硬编码

### 安全内建

- [ ] 用户输入经过校验后再使用（不信任前端参数）
- [ ] SQL 参数化（无字符串拼接）
- [ ] 日志不打印敏感信息（密码、token、身份证、完整手机号）
- [ ] 接口返回不包含多余的内部字段

### 可测试性

- [ ] 核心逻辑可独立测试（不强依赖 Spring Context / 数据库 / 网络）
- [ ] 外部依赖可 Mock（通过接口注入，不在方法内部 new）
- [ ] 测试数据不依赖生产环境

## 与 AI 生成代码的额外检查

- [ ] AI 未引入项目中不存在的依赖/库
- [ ] AI 未改变项目已有的公共方法签名（影响其他调用方）
- [ ] AI 未在 Task Contract 范围外添加 "顺手改的" 代码
- [ ] 生成的代码风格与项目一致（缩进、换行、import 顺序）

## Fast Path

单文件小改、无架构影响 → 最小检查：命名 + 错误处理 + 安全内建。

## Full Path

上表全部勾选；review 记录可落 `docs/review/<domain>/`。
