# Project Elements

用于从项目中提取那些真正有助于后续开发的元素，不是为了做一份全面项目介绍。

## 核心原则

只提取对后续开发准确性有直接帮助的元素：

- 边界
- 入口
- 主链路
- 高频变更点
- 最小验证方式

如果一个元素不能帮助 AI 更快定位或更稳执行，就不要优先提取。

## 提取优先级

### P0：直接影响开发定位

- 模块边界
- 真实入口
- 主调用链
- 关键状态变化点
- 高频变更点

### P1：补充理解但不必先读

- 目录结构
- 命名约定
- 核心约束
- 常见异常入口

### P2：复杂场景再补

- 长背景说明
- 设计历史
- 低频扩展点
- 非主链路的次要细节

## 六类高价值元素

### 1. 边界

提取：

- 系统边界
- 模块边界
- 子模块边界

作用：

- 防止 AI 改错模块
- 帮助 skill 定义 scope

### 2. 入口

提取：

- Controller
- Job
- Listener
- Consumer
- RPC / Client / Command

作用：

- 让 AI 先找到从哪里进入

### 3. 主链路

提取：

- 入口到核心处理
- 核心处理到存储 / 外部系统
- 关键状态变化位置

作用：

- 让 AI 能复述系统怎么真正工作

### 4. 高频变更点

提取：

- 枚举
- 配置 key
- 策略 / 工厂 / 路由
- 抽象接口与实现类
- 校验器
- 关键表与状态字段

作用：

- 让 skill 能回答“新增 / 修改 / 对接 / 排查”改哪

### 5. 最小 SOP 素材

提取：

- 先看哪里
- 再改哪里
- 最后怎么验

作用：

- 直接为 skill 的 SOP 提供原料

### 6. 最小验证素材

提取：

- 真实任务样本
- 回归检查点
- 失败链路或边界链路样本

作用：

- 让 skill 不只是“看起来合理”，而是真的可验证

## 反模式

- 把项目总览当成 skill 核心内容
- 先提取低频背景而不是主链路
- 提取大量元素但不服务具体开发场景
- 有目录，没有入口；有架构，没有切入点
