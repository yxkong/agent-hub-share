# 技能设计理念（通用）

与具体项目无关，适用于任意代码库的技能创建、优化与提炼。

---

## 一、核心价值

技能的价值不是“写全知识”，而是让 AI 在面对陌生代码库、老项目、现有 SKILL 或接口文档时，稳定做到三件事：

1. 快速定位改动位置
2. 保持实现与维护方式一致
3. 能在真实任务里持续迭代，而不是停留在纸面规范

---

## 二、默认交付标准

默认交付标准是：`standard = 五要素完整版`。

五要素是：

1. 设计理念
2. 流转图 + 数据流
3. 切入点
4. AI 开发者使用 SOP
5. 核心示例

只有在轻量内部技能、单一任务型技能、临时桥接技能等场景下，才允许降为 `lite`。如果进入高复杂度、高复用、高风险场景，再升级为 `full`。

---

## 三、为什么主文件只做路由器

主文件的任务不是把方法论讲完，而是让 AI 在最短时间内做对三件事：

- 识别当前任务属于哪一类
- 打开正确的第一篇 reference
- 不要误读不必要的内容

因此：

- 高频、低歧义信息放主文件
- 细节流程、长样例、长规则放 references
- 平台专属内容不放默认阅读链

---

## 四、设计理念

| 理念 | 说明 | 约束 |
|------|------|------|
| 真实任务优先 | 先判断 create / extract / review / refine-trigger，再决定结构 | 不允许跳过任务识别直接套模板 |
| 以快速切入为核心 | 技能首要目标是帮助 AI 快速定位与执行 | 切入点必须落到具体类 / 方法 / 表 / 文件 / 文档 |
| 主链路优先于边角 | 先抓入口、主流程、状态流转，再补旁支 | 主链路没清楚前不先堆背景资料 |
| 可驱动开发优先 | skill 的价值先看能否指导真实开发 | 不能驱动开发的漂亮结构也不算合格 |
| 渐进式披露 | 主文件只做总纲，细节在 references | 主文件不重复展开完整 references |
| 验证驱动迭代 | 技能靠真实提示、真实任务和正负例校正 | 修改后不能只做格式检查 |

---

## 五、自由度策略

| 自由度 | 适用场景 | 推荐形式 |
|--------|----------|----------|
| 高 | 多种方案都合理，主要是给方向 | 原则、判断规则、反模式 |
| 中 | 有推荐模式，但允许变体 | 模板、骨架、路由表 |
| 低 | 易出错、强一致性、高复用 | 固定 SOP、脚本、字段映射、验证步骤 |

经验法则：

- 结构要求可以更明确
- 实现细节保留合理自由度
- 对存量提炼类技能，优先把提取流程写死，把业务命名留给上下文

---

## 六、反模式

### 主文件行数（按类型分级）

**计数口径**：与父技能 `skill-engineering` 的 `SKILL.md` 一致——仅统计 **trim 行首行尾空白后仍非空** 的物理行；纯空行不计；标题、表格、列表、代码块内容等均计入。

**核对（须用 hub `check-skill-size.sh` / `check-skill-size.ps1`，禁止自拼 `awk`）**：

`bash "$AGENTS_HUB_ROOT/scripts/check-skill-size.sh" --file path/to/SKILL.md` 或加 `--type meta` / `--max N` 做门禁。

| Skill 类型 | 特征 | 非空行上限 |
|-----------|------|---------|
| 纯路由器 | 只有路由表 + 简单边界，无内嵌规则/模板 | 80 |
| 路由器 + 硬约束 | 路由表 + 平台专属硬规则（不可下移到 references） | 130 |
| 多域路由器 | 路由条目 ≥ 15，需要分组标题 | 150 |
| 元技能 | skill-engineering 等协议性内容，主文件即规则本身 | 160 |

超过对应类型非空行上限立即拆分；新章节内容下移 references/*.md，主文件保留一行指针。（出现 ≥ 2 次，已提升为顶层条目）

### References 深度（最多两级）

**计数口径**：仅统计 `references/` **直接下一级**的 `*.md` 文件，**排除** `references/bak/`（含其下文件）。**≤15** → 1 级 flat；**≥16**（多于 15）→ 须 2 级 subdir。

| 层级 | 适用场景 | 限制 |
|------|---------|------|
| 1 级 flat | 顶层 `*.md` **≤15** | 默认，无额外限制 |
| 2 级 subdir/ | 顶层 `*.md` **>15** 且有清晰语义分组 | 子目录名必须是语义词（`rag/` `chat/`）；每子目录内 `*.md` **≤15** |
| 3 级及以上 | 禁止 | — |

2 级使用约束：主文件路由表链接精确到具体文件（`references/rag/RG01.md`），不能链接到目录；子目录内禁止再创建子目录；跨子目录引用（`../chat/`）禁止。

### 其他反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 跨运行时对齐绕过共享契约 | 复制参考项目内部架构、前端叠产品名、DB 补丁或固定预算，让“效果一致”变成多套实现耦合 | 先冻结 versioned observable contract + 同源 golden；平台/垂类/Skill/前端按所有权实现；契约变更双端对拍，禁止产品分支、DB workaround 和长期兼容壳 |
| 默认 full 化 | skill 变得很重，维护成本高 | 默认 `standard`，高复杂度再升 `full` |
| 只看结构不看可用性 | 技能漂亮但驱动不了开发 | 优先验证入口、主链路、切入点和 SOP |
| 平台专属内容混入默认链 | 非当前环境时会误导 AI | 平台专属内容放 P2 按需阅读 |
| references 职责重叠 | 多篇文档都在讲同一件事 | 明确"为什么 / 长什么样 / 怎么做 / 怎么验"边界 |
| 子技能合并不彻底 | 子技能重定向后 references 仍以跨目录路径引用 | 合并时物理迁移 references/*.md 到主技能，更新所有链接为相对路径 |
| 价值门禁缺失 | 经验提炼类 skill 把规则违规、普通 bug、AI 未遵守规则导致的返工包装成能力资产 | 先做输入范围隔离和价值门禁；遵循既有 SQL/工程规范即可避免的问题不入资产；主表达必须让外部读者看懂"原系统问题 -> 解决方案 -> 效果"，内部编号只进证据附录 |
| 增量 review 陷阱 | 每次只修一个 finding，下一轮才发现同类漂移，导致用户反复追问"再全量 review" | 对完整产品型 skill 必须先做全量文件清单，再做至少两轮交叉审查：主流程、脚本行为、文档承诺、模板、示例、生成物；最后一次性输出所有剩余问题 |
| 脚本能力未暴露 | 底层 Python/内部实现支持某能力，但 `.ps1` / `.sh` 标准入口未暴露，迫使模型绕过脚本拼内部命令 | 所有用户可用能力必须通过标准跨平台 wrapper 暴露；新增 flag 时同步 PowerShell / POSIX 两端、用法注释和相关文档 |
| 文档-脚本契约漂移 | 脚本行为已改，但 README、模板、reference 或注释仍保留旧规则，低级模型按旧文档执行 | 改脚本必须同步 grep 旧关键词，更新 README / references / templates / 示例 / 生成物说明；脚本通过不等于产品闭环通过 |
| 机器索引伪身份 | 为缺失 id 的资产生成路径 hash 或占位 id，导致非资产文件进入索引或路径变化产生新身份 | 资产身份必须由真实源显式声明；机器索引只收 canonical 事实源；缺必需 id 默认失败，审计模式也只能跳过并报告，不得伪造身份 |
| 跨平台 wrapper 漂移 | `.ps1` 与 `.sh` 参数语义、错误策略或解析行为不一致，某一端可用另一端卡死/静默覆盖 | 双平台脚本必须同语义：同参数、同默认失败策略、同审计模式；shell 参数分支必须消费参数，PowerShell 参数必须显式声明；至少做语法/主路径/新增 flag 自测 |
| 用尺寸修补信息架构 | 复杂页面只调弹窗/抽屉宽度、label 或滚动容器，仍让每个页面复制布局样式 | 先做信息架构分流：配置型 tabs、流程型 steps、过重则独立页面；可复用布局必须沉到公共组件/公共样式/公共 hook，不在业务页重复写 drawer body/footer/width |
| 多套路由并存 | `SKILL` + `README` + `INDEX` + 关键词表都可当 Agent 入口，路由漂移 | **仅** `SKILL.md` §2 为任务入口；meta 文件头 blockquote 禁止 Agent 入口；人类速查与 catalog 分离 |
| handbook 与 rule card 同级 | 500+ 行规约/百科与 ≤150 行 SOP 同 tier，Agent 通读 token 爆炸 | 大文档进 `references/handbook/`（P2）；SKILL 标注「按需检索、禁止通读」；旧路径留 stub |
| Review 误开 handbook | review/重构默认打开反模式/规约全文，或跳过 `quick_gate.md` 直接吞系统详表 | 默认先 `review/quick_gate.md` 判阻断与下一步；系统修复再进 checklist；handbook 仅 J-xxx/章节检索 |
| 无价值中转索引 | SKILL 已能直达 active reference，仍保留 `modes/*.md` 或 redirect stub 让 Agent 多读一层，并产生路由漂移 | 无外部依赖时删除中转文件及 INDEX 条目；把必要顺序和裁决直接放进 SKILL 路由 |
| 搬迁丢正文 | Move 后 handbook 被 stub 覆盖或 git 编码损坏 | 先 backup → 迁正文 → 写 stub → grep 交叉引用；验证 handbook 文件大小与首段标题 |
| bak 内可发现 SKILL.md | dated 快照或 `bak/**` 仍保留 `SKILL.md` 文件名，污染 discovery/review/Agent 触发 | **禁止** skill 树下非 canonical 路径出现 `SKILL.md`；备份用 `_SKILL.md` / `SKILL-<stamp>.md` / `SKILL_md/`；`check-skill-entrypoints` 必须 fail；`find-skills` 只列 canonical |
| 挂载入口当真源 | 在 `.cursor/skills/` 等工作区入口改正文，与 hub 漂移 | 正文只改 hub 真源；挂载仅经 `agent-hub-bootstrap` 脚本；见 `skill_truth_source_contract.md` |
| Harness 自锁 | 写入 Guard 连自己的状态查询、撤销或恢复命令也拒绝，导致只能删除 Hook | 恢复控制面永远可用并做真实 Hook 回归；业务写入仍 fail closed |
| 确认循环 | 用户已明确要求实施，仍为设计 Hash、引用方、测试或新增文件逐次重签 | 一次目标授权覆盖同一目标的设计、依赖闭包、实现和验证；只在目标越界或高风险动作前再次确认 |
| Canonical 范围替换 | 用同一路径把原 Spec/SDD 的业务范围替换为另一主题，导致旧需求失去真源 | 新主题使用新身份或显式兼容演进；发布前做需求 ID、索引和引用反查，禁止静默覆盖 |
