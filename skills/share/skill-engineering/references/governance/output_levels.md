# Skill 输出级别

## 选择决策

```
输出级别
├── standard（默认）── 大多数场景
├── lite ────────── 轻量、单任务、临时
└── full ────────── 跨团队、高风险、高复杂度
```

---

## lite

**适用**：轻量内部技能、单一任务型技能、先求可用不求全量文档化。

**最少包含**：

- 作用边界
- 切入点（精确到类 / 方法 / 文件）
- 最小 SOP（3 步以内可完成主任务）
- 1 个验证样例

省略其他要素时须注明原因。

---

## standard（默认）

| 要素 | 说明 |
|------|------|
| 设计理念 | 边界、核心约束 |
| 流转图 + 数据流 | 外部对接类必须有 Mermaid 图 |
| 切入点 | 精确到类 / 方法 / 表 / 文件，不写抽象分层 |
| AI 开发者使用 SOP | 动作化步骤，覆盖新增 / 修改 / 排查场景 |
| 核心示例 + 验证 | 至少 1 条真实任务可验证 |

省略某要素时，必须写明：省略了什么、用什么替代、为什么不影响定位和验证。

---

## full

**适用**：跨团队复用、高风险、高复杂度、需要更强触发与验证支撑的技能。

`full = standard` 加强版，额外交付物见 `review/full_mode_checklist.md`。

---

## 升降级规则

- 默认从 `standard` 起步，稳定后根据实际使用情况升/降。
- 发现 `lite` 技能被高频使用且 SOP 不足 → 升 `standard`。
- 跨团队、高复杂度场景用 `standard` 无法驱动开发 → 升 `full`。
- 不允许因懒直接选 `full`，先问：standard 能不能解决问题。
