# 评分校准样例

> 用于防止评分虚高。打分前先对照本文件选择最接近的档位；没有足够证据时，分数只能落在较低证据档。

## 96+ 标杆档

必须同时满足：

- `SKILL.md` 是纯运行入口：30 秒内能判断路由、首读文件和红线
- README 是维护章程，references 是细则；三者没有并列入口或重复真源
- 至少 3 个不同类型真实任务有 `executed` / `observed` 证据
- 高风险 / 纪律类 skill 有无 skill 基线样本与带 skill 复测样本
- 经历优化的 skill 有 baseline rollout、reflection、bounded edit 与 held-out validation 记录
- share skill 的 96+ 证据来自可迁移动作规则和通用验证，不把项目技能、账号资料或当前运行环境装配成功算成本体能力
- 校验脚本、触发样例、模板与派生资产一致，且无私有耦合

典型结论：`可挂载`，且可以作为同类 skill 模板。

## 90-95 优秀档

满足大部分标杆条件，但仍有一类证据不足：

- 结构清晰，首读成本低
- 主要能力有 active 文件承接
- 静态校验通过
- 真实触发或行为复测样本不足，或只覆盖 1-2 个任务类型

典型结论：`可挂载 / 可复用`。不能因为“写得很好”直接给 96+。

## 80-89 可用档

能力基本存在，但仍有明显工程债：

- 主文件偏厚，或 references 分层不够干净
- 验证方式存在但没有完整执行证据
- 模板、README、索引存在轻微漂移
- 行为有效性只能静态推断

典型结论：`可复用`，部分场景可挂载，但不应作为标杆。

## 70-79 仅参考档

有可借鉴内容，但不适合直接挂载：

- description 或边界不准
- SOP 有启发但无法直接驱动行动
- 缺少脚本验证或路径有效性证据
- 只看单文件无法确认完整能力包

典型结论：`仅参考`。

## 低于 70 暂缓档

满足任一条应进入暂缓：

- 关键路径、脚本或入口失效
- 承诺能力没有 active 文件支撑
- share 资产硬编码真实项目私有信息
- share 能力结论依赖项目技能、账号资料或当前运行环境装配结果
- 缺契约、缺 SOP、缺验证闭环

典型结论：`暂缓使用`。

## 反通胀规则

- 没有 `executed/observed` 证据，默认不得给 96+
- 只盘点 `SKILL.md`，不得给最终高分
- 长手册型 skill 可以兑现高，但质量分要扣首读效率和主文件纯度
- “看起来全面”不是高分理由；必须证明触发后能让 Agent 更快、更稳、更少返工
