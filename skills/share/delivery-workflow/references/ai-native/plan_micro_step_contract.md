# 计划微步契约

> P1 增强协议。用于 Full Path 计划、Task Contract 或准备派发给零上下文执行者的任务清单。

## 执行者画像

计划头部必须默认假设执行者：

- 对当前仓库零上下文。
- 不擅自做品味判断或范围扩展。
- 只能按精确路径、代码块、命令和验收判据执行。
- 遇到缺口时返回 `NEEDS_CONTEXT`，不得用猜测补齐。

## 微步粒度

每一步应能在 2-5 分钟内完成，并同时具备：

- 精确文件路径。
- 明确动作：读、改、运行、核对、记录。
- 完整代码 / 命令 / 检查点。
- 预期输出或失败形态。

示例：

```markdown
- [ ] Step 3: 更新 `references/publish/doocs_and_checklist.md`
  - 动作：新增“标题已过打分门”检查项。
  - 验证：`rg "标题已过打分门" references/publish/doocs_and_checklist.md`
  - 预期：命中 1 行。
```

## 禁止占位符

计划出现以下表述即不合格：

- `TODO`、`TBD`、`后续补充`、`待完善`。
- “添加适当错误处理”、“按需优化”、“处理边界情况”。
- “类似上一步处理其余 N 个”。
- “写对应测试”但没有测试文件、测试名、命令和预期失败 / 通过输出。
- “参考现有实现”但没有给出参考文件路径。

## 自检

交付计划前至少扫一遍：

- 每个任务是否有范围白名单和禁止改清单。
- 每个步骤是否能独立执行，不依赖口头上下文。
- 验证命令是否有通过判据。
- 失败时是否能落入 `DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED`。
