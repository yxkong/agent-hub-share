# Reference Implementation Gate

跨模块重构、技术栈迁移、全仓架构收口、以及准备派发给其他模型/子 Agent 的任务，必须先过“样板先行门”。

## 触发条件

命中任一条件即触发：

- 用户要求“全部模块”“全链路”“统一标准”“不要过渡”“最终版”。
- 任务影响 3 个以上模块，或会改变公共基类、DI、路由、事务、协议模型。
- 需要把任务派发给 Gemini、子 Agent 或外包执行者。
- 过去已经出现因规则模糊导致接口不可访问、协议不对齐、DI 偏航、兼容壳残留。

## 必须先产出

```text
[样板先行门]
目标:
不可变外部契约:
参考样板:
范围白名单:
范围黑名单:
分层落点:
验证命令与判据:
停止条件:
派发状态协议:
```

任何项为空，不允许进入批量实现或派发。


## 脚本选择

- 复杂文本写入、批量文件扫描、跨平台校验默认使用 Python。
- PowerShell 只用于简单命令编排、调用既有 .ps1 工具或 Windows 专属操作。
- 禁止为了写 Markdown/代码生成临时 PowerShell here-string 脚本；能用 `apply_patch` 直接改就直接改，需要脚本时优先 Python。

## 执行规则

- 先完成一个样板模块的写入、读取、响应出口三联检，再推广同型模块。
- 主模型负责架构判断、样板选择、验收口径；执行模型只能机械落盘。
- 执行模型不得新增兼容层、过渡容器、第二套基类、第二套协议名。
- 如果发现样板不覆盖当前场景，返回 `NEEDS_CONTEXT`，不得自行扩展标准。
- 不得把“能编译”当完成；必须证明用户可访问主链路。

## 派发 Prompt 必备 7 要素

1. 目标：一句话说明最终状态。
2. 范围白黑名单：精确到路径/模块。
3. 输入上下文：样板文档、真源文件、已知事实。
4. 硬约束：不可变契约、禁止事项、分层职责。
5. 步骤：只包含机械执行步骤，不包含开放式探索。
6. 验证命令与判据：命令、通过标准、失败输出要求。
7. 输出四态：`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`。

## 停止条件

- 需要决定架构取舍。
- 找不到 Java / 前端 / 当前 Python 真源。
- 验证命令无法执行且没有可替代证据。
- 修改会破坏外部契约。
- 必须引入临时兼容层才能继续。

触发停止条件时，执行者必须停止并汇报事实。
