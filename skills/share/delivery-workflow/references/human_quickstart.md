# Delivery Workflow 人类速查

> 本文件给**人**快速理解 `delivery-workflow` 用，**禁止 Agent 当入口**。
> `SKILL.md` 仍保持给 AI 的高密度执行协议；不要把本文件的口语化表述反向抄回主文件。

## 先看这张表

| 你现在遇到什么 | 先过哪一关 | 立刻做什么 | 先别做什么 |
|---|---|---|---|
| 报错、异常、数据不对、功能不符合预期 | `debug` 路由 | 先读 `references/debug_workflow.md`，确认现象、根因、影响面 | 不要急着改代码 |
| 需求明确、改动小、验证清楚 | Fast Path | 写最小设计，直接进实现 | 不要把小改升级成大重构 |
| 字段/接口/权限还没定，或前后端一起动 | Full Path | 先把目标、边界、契约、验证路径写清楚 | 不要前后端同时开写 |
| 多文件机械改动、逐表治理、整批同步 | 执行档硬触发 + R2 | 主模型拆白名单和验收，派 **slug 以 `-fast` 结尾** 的执行档模型 | 不要主模型手工大面积落盘 |
| 用户质疑“你没改”“验收没过” | `Gate 4 验证完成` + `R3` | 补验证证据、补失败沉淀 | 不要只回复“下次注意” |

## 一句话记忆

- **先判断路由**：`debug / frontend / backend / fullstack / checklist`
- **再判断规模**：小改走 Fast Path，契约未定或跨端走 Full Path
- **实现前看 R1/R2，失败后看 R3**

## 五步推进

### 1. 先理解需求

对应 `SKILL.md` 的 `阶段门速记` / `Gate 1 需求理解`。

- 先分清：用户想解决什么、现在看到的现象是什么、怀疑的根因是什么
- 不要把用户随口给的方案直接当最终需求
- 不要把暂时边界当成真实边界

### 2. 先对齐方案

对应 `SKILL.md` 的 `阶段门速记` / `Gate 2 设计收敛`，以及 `Fast Path / Full Path`。

- 实现前至少写清：目标、边界、契约、风险、验证路径
- 如果是 Full Path，先发散 2-3 个方案，再收敛到一个
- 如果最小设计写不出来，就不应该进入实现

### 3. 再拆最小闭环

对应 `SKILL.md` 的 `阶段门速记` / `Gate 3 实现推进`。

- 一次只推一个最小闭环
- 先做主链路，再做异常和边界
- 进下一步前先看 `git status` 或等价工作区状态

### 4. 做完要有证据

对应 `SKILL.md` 的 `阶段门速记` / `Gate 4 验证完成`。

- 主链路已验证
- 关键失败链路已覆盖
- 文档 / SQL / 配置说明已落到正确位置
- 若现象是“HTTP 200 但缺数据”，别忘了三联检：写入 → 查询 → 响应出口

### 5. 失败不白费

对应 `SKILL.md` 的 `阶段门速记` / `Gate 5 失败沉淀` 与 `R3`。

失败后至少要回答两件事：

1. 这次失败属于哪类：需求理解、设计漏项、契约不清、切分不当、验证不足？
2. 沉淀到哪里最合适？

| 沉淀类型 | 用哪个技能 | 给谁看 |
|---|---|---|
| 认知洞察 / 方法论 / 面试表达 | `project-insight-extractor` | 人 |
| 反模式 / 触发约束 / 技能回填建议 | 相关 `SKILL.md` 或 `references/anti_patterns*.md` | Agent |
| 可复用子 Agent prompt | `prompt-engineering` | Agent |

## R1 / R2 / R3 怎么记

| 规则 | 人类记忆法 | 什么时候看 |
|---|---|---|
| `R1` | 实现前先报路由 | 写代码 / 改文件 / 派子 Agent 前 |
| `R2` | 派子 Agent 要有完整说明书 | 用执行档 fast 模型前 |
| `R3` | 失败要沉淀，不要空复盘 | 返工 / 漂移 / 验收没过后 |

## 什么时候看本文件

- 新人第一次接手 `delivery-workflow`
- 人类 reviewer 想快速理解这套流程
- 觉得 `SKILL.md` 太像“协议”而不是“说明书”时

## 什么时候不要看本文件

- 需要按规则精确执行时：直接看 `SKILL.md`
- 需要派子 Agent 时：看 `references/subagent_prompt_template.md`
- 需要具体路由细节时：看 `references/*_workflow.md`
